# Toolshop 电商系统测试方案

## 一、项目概述

### 1.1 项目名称

基于 Toolshop 的电商 Web 系统质量保障实践。

### 1.2 项目背景

本项目以 Practice Software Testing 提供的 Toolshop 电商演示系统为被测对象，模拟实际软件测试工作流程，围绕商品浏览、商品搜索、商品筛选、用户登录和购物车等核心功能开展测试。

项目以功能测试和测试用例设计为主，结合风险分析、缺陷记录及 Python 自动化测试，形成较完整的质量保障实践过程。

### 1.3 项目目标

1. 熟悉 Web 电商系统的基本业务流程。
2. 掌握测试需求分析、测试用例设计和测试执行的基本方法。
3. 从功能、异常、边界和业务规则等角度识别潜在风险。
4. 学习使用 Python 和 pytest 编写基础自动化测试。
5. 通过测试记录、缺陷分析和测试总结，提高测试结果的可追溯性。

## 三、测试范围

### 3.1 计划测试的功能

| 模块 | 测试内容 | 优先级 |
|---|---|---|
| 商品浏览 | 商品列表展示、商品信息显示 | 高 |
| 商品搜索 | 关键词搜索、无结果搜索、搜索结果准确性 | 高 |
| 商品筛选 | 商品分类筛选、筛选结果准确性 | 高 |
| 商品详情 | 商品名称、价格、图片及详情展示 | 高 |
| 购物车 | 添加商品、商品数量和购物车状态变化 | 高 |
| 用户登录 | 登录页面、输入校验、正确及错误凭据处理 | 高 |
| 订单流程 | 结算、订单提交及相关业务校验 | 中 |
| 界面与交互 | 页面布局、按钮响应、提示信息 | 中 |

注：以上为计划测试范围，实际可测试的功能以当前演示系统的页面和可用权限为准。

### 3.2 暂不纳入的测试范围

1. 大规模性能测试与压力测试。
2. 真实支付及真实交易验证。
3. 生产环境安全测试。
4. 复杂的多浏览器兼容性测试。
5. 暂时无法访问或需要额外权限的功能。

## 四、测试策略

### 4.1 功能测试

验证各项功能是否符合预期，重点检查正常操作、异常输入和业务规则。

### 4.2 等价类划分

将输入数据划分为有效等价类和无效等价类。例如，商品搜索可以考虑有匹配结果的关键词、无匹配结果的关键词以及空关键词。

### 4.3 边界值分析

关注可能影响功能表现的边界情况，例如搜索框为空、商品数量变化以及表单必填项缺失等。具体边界以系统实际规则为准。

### 4.4 场景测试

从用户实际使用流程出发，验证商品浏览、搜索、查看详情、加入购物车等操作之间的衔接是否正常。

### 4.5 异常测试

尝试错误输入、缺少必填信息、重复操作及其他合理的异常场景，检查系统提示和处理结果。

### 4.6 自动化测试

在完成手工测试和业务流程梳理后，选择稳定、重复执行价值较高的功能开展自动化测试。优先考虑接口测试；如果接口条件不满足，再根据实际情况调整方案。

## 五、测试执行流程

1. 熟悉系统功能，梳理业务流程。
2. 分析需求与风险，确定测试范围。
3. 设计测试用例并进行检查。
4. 执行测试用例，记录实际结果。
5. 对发现的异常进行复现和分析。
6. 记录经确认的缺陷，并保留必要的复现信息。
7. 对适合自动化的场景编写并执行自动化脚本。
8. 汇总测试结果，分析遗留风险并编写测试总结。

## 六、缺陷管理

对于测试过程中发现的异常，记录以下信息：

- 缺陷编号
- 缺陷标题
- 所属模块
- 测试环境
- 前置条件
- 复现步骤
- 预期结果
- 实际结果
- 严重程度
- 缺陷状态
- 截图或其他辅助证据

只有经过实际操作、能够描述清楚复现步骤的异常，才作为已发现缺陷记录。尚未验证的问题应记录为待验证风险或测试建议，不直接认定为缺陷。

## 八、测试风险与注意事项

1. 演示网站可能更新、重置数据或出现临时不可用的情况，应记录测试时间和环境。
2. 在线演示系统可能存在权限和数据限制，测试范围需要根据实际情况调整。
3. 自动化脚本可能受到网络波动、页面变化及测试数据变化的影响。
4. AI 生成的测试用例和代码需要经过人工检查，不应未经验证直接作为测试结论。
5. 不进行真实支付、破坏性操作或对其他用户数据的修改。
6. 测试结果必须基于真实执行记录，不虚构缺陷数量、通过率或自动化覆盖率。

## 九、测试完成标准

1. 计划范围内的核心功能已完成测试，或已说明无法执行的原因。
2. 测试用例具有明确的前置条件、操作步骤和预期结果。
3. 实际执行结果有记录，失败项有相应说明。
4. 已确认的缺陷有可复现的信息；未解决的问题和遗留风险已说明。
5. 自动化测试能够在记录的环境中执行，执行结果真实可查。
6. 已形成测试总结，能够说明测试范围、执行情况、主要发现和后续改进方向。
