# Toolshop 电商 Web 系统测试总结报告

## 1. 项目概述

### 1.1 项目背景

本项目以 Toolshop 电商 Web 系统为测试对象，使用 With Bugs 在线演示版本开展 Web 功能测试与自动化测试实践。测试围绕商品搜索、分类筛选、商品详情、购物车等核心业务场景，并结合异常输入和边界条件观察系统表现。

项目重点是通过测试用例设计、实际执行、异常分析、缺陷记录和测试总结，展示 Web 系统质量保障的基本流程，而非单纯堆叠自动化脚本。

### 1.2 测试目标

- 验证商品浏览、搜索、分类筛选、商品详情及购物车等功能的基本行为。
- 覆盖正常流程、异常场景和边界输入，识别潜在质量风险。
- 对发现的异常记录复现步骤、预期结果、实际结果和相关证据。
- 使用 Playwright 对首页和购物车关键流程开展 UI 自动化验证。
- 形成可追溯的测试用例、缺陷记录、自动化代码及测试总结。

- **功能测试：** 检查功能是否符合预期。

- **边界值测试：** 检查数量为 0、负数、小数等输入。
- **异常场景测试：** 观察异常操作时的提示与页面状态。
- **一致性检查：** 对比商品价格、购物车行内金额及底部总价。
- **状态保持检查：** 验证刷新后商品和数量是否保留。
- **UI 自动化测试：** 使用 Playwright 模拟用户操作，并通过断言检查页面行为。

## 4. 缺陷与风险分析

当前 `bugs/缺陷记录.csv` 中记录 BUG-001 至 BUG-006 共 6 条问题。以下为异常现象及其潜在影响；缺陷最终状态以 CSV 中的最新记录为准。

| 编号 | 异常现象 | 潜在影响 |
|---|---|---|
| BUG-001 | 加入购物车后页面出现错误提示，但商品实际已添加 | 页面反馈与实际状态不一致，可能引起用户困惑或重复操作 |
| BUG-002 | 商品行内金额显示为 `$00.00`，但底部总价能够正确计算 | 用户无法准确核对单个商品金额 |
| BUG-003 | 点击商品删除按钮后，商品仍保留在购物车中 | 用户可能无法正常移除商品 |
| BUG-004 | 重复添加已有商品时出现错误提示，商品数量未增加 | 影响购物车商品数量更新 |
| BUG-005 | 注册后使用相同凭据登录失败 | 需要结合账号创建状态和环境要求判断问题归属 |
| BUG-006 | 商品数量为 0 时购物车入口消失 | 用户可能无法通过该入口继续查看或修改购物车 |

### 4.1 页面提示与实际状态不一致

BUG-001 的本次自动化结果显示，点击添加按钮后出现错误提示，但购物车数量仍增加至 1。测试时不能只依据提示文案判断操作是否成功，还需要检查购物车数量和商品清单的实际状态。如果用户将错误提示理解为操作失败并重复点击，可能造成困惑或重复操作。

### 4.2 购物车金额展示

BUG-002 的本次自动化结果显示，商品单价为 `$14.15`、数量为 1，行金额显示 `$00.00`，底部总价为 `$14.15`。这表明行金额展示与底部总价需要分别检查；底部总价正确并不能抵消行金额显示异常对用户核对金额造成的影响。

### 4.3 删除商品与页面数据就绪

BUG-003 的有效执行中，点击红色删除按钮后商品仍显示在购物车中，数量仍为 1。另一次独立重跑因商品列表未加载而在操作前超时，未执行删除动作。两种情况需要区分：前者是一次有效的异常观察，后者是页面数据未就绪，不能当作删除操作的测试结果。

### 4.4 其他记录

BUG-004 至 BUG-006 属于已有缺陷记录。本报告保留其现有描述，不根据本次 5 项 UI 自动化结果推断这些问题已被重新验证。

## 6. 测试限制

1. **环境限制：** 测试依赖在线演示环境，网络、服务端状态和页面数据可能影响执行。
2. **范围限制：** 本次 UI 自动化仅包含 5 项用例，覆盖首页和部分购物车核心行为，不代表完整的端到端回归测试。
3. **账号限制：** 注册与登录流程尚未完成全面验证。
4. **自动化限制：** 一次独立删除流程因商品列表未加载而未执行到删除操作，说明脚本运行还可能受到页面数据就绪情况影响。
5. **根因分析限制：** 测试记录的是可观察到的页面行为，不一定能确认服务端根本原因。
6. **修复验证限制：** 项目主要针对 With Bugs 演示站进行测试实践；未执行或未确认的修复状态不作推断。

## 8. 总结

本项目已开展手工功能测试，并使用 Playwright 对 With Bugs 网站首页及购物车关键流程进行了首轮 UI 自动化验证。本次自动化共执行 5 项用例，2 项通过、3 项失败；失败结果分别对应加入购物车后的错误提示、购物车行金额显示异常和删除商品后商品仍保留三种现象，并关联至已有的 BUG-001、BUG-002、BUG-003 记录。

本次 UI 执行也暴露出自动化测试对页面数据就绪的依赖：一次独立删除流程重跑未加载出目标商品，因此没有执行删除动作，未纳入完整运行统计。后续 UI 代码将此类情况标记为前置条件未满足；该改动尚待运行验证。项目当前已形成测试用例、UI 自动化代码、CSV 缺陷记录、截图证据目录和测试总结等交付物。

本报告中的执行数量和观察结果依据 Day5-购物车UI自动化执行摘要。测试失败率仅适用于这 5 项自动化用例，不能外推为系统整体质量结论。后续重点是保证证据可追溯、区分有效执行与环境导致的无效运行，并让缺陷状态与真实复测结论保持一致。
