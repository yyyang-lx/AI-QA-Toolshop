# Toolshop 电商 Web 系统测试总结报告

## 1. 项目概述

### 1.1 项目背景

本项目以 Toolshop 电商 Web 系统为测试对象，围绕用户浏览商品、搜索商品、筛选商品及购物车操作等核心业务场景开展功能测试，并结合异常输入和边界条件检查系统表现。

项目采用 With Bugs 在线演示版本，重点关注功能正确性、页面反馈与实际执行结果的一致性，以及异常场景下的系统行为。

### 1.2 测试目标

- 验证商品搜索、分类筛选、商品详情及购物车等核心功能的基本表现。
- 通过正常场景、异常场景和边界值场景发现潜在问题。
- 记录可复现的异常现象，并分析其可能造成的用户影响。
- 形成测试用例、缺陷记录和测试报告等质量保障交付物。
- 为后续核心场景自动化测试及项目面试讲解提供依据。

## 2. 测试范围与方法

### 2.1 测试范围

本轮测试主要覆盖以下模块：

| 模块 | 主要测试内容 |
|---|---|
| 商品搜索 | 正常关键词、无结果关键词、空格输入、切换关键词 |
| 商品分类筛选 | 分类筛选、取消筛选、切换分类、组合筛选 |
| 商品详情 | 页面展示、商品名称与价格一致性、购买数量 |
| 购物车 | 添加商品、重复添加、数量修改、金额计算、删除商品、刷新后的状态 |
| 注册与登录 | 页面展示、部分登录异常场景及注册后的登录尝试 |
| 边界与异常输入 | 数量为 0、负数、小数及非数字输入 |

注册与登录模块受测试账号创建状态影响，尚未完成完整业务流程验证。

### 2.2 测试方法

- **功能测试：** 验证主要功能是否能够按预期执行。
- **等价类测试：** 选择有效和无效输入进行验证。
- **边界值测试：** 检查商品数量为 0、负数、小数等输入。
- **异常场景测试：** 观察操作失败时的提示及页面状态。
- **一致性检查：** 对比商品列表与详情信息、购物车行内金额与底部总价。
- **状态保持检查：** 验证刷新页面后购物车商品及数量是否保留。

本轮以手工测试为主，自动化测试尚未形成完整的回归验证体系。

## 3. 测试执行与结果概述

当前测试用例表包含 TC001–TC034，共 34 条用例记录，具体执行状态以 `testcases/测试用例.xlsx` 中的最新记录为准。

本报告不单独计算测试通过率，因为部分用例仍处于待判断或待确认状态，且尚未对所有记录进行最终统计。

### 3.1 表现正常的场景

根据现有执行记录，以下场景在已测试条件下表现正常：

1. 商品搜索能够返回匹配结果，无匹配商品时能够显示无结果状态。
2. 商品分类筛选、取消筛选及部分组合筛选能够正常工作。
3. 商品详情页能够展示商品名称、价格等信息，且已核对的列表与详情信息一致。
4. 在已验证的数量修改场景中，购物车底部总价能够正确计算。
5. 刷新页面后，已添加商品及其数量能够保留。
6. 输入小数数量后，系统会将数量恢复为整数。

以上结果仅代表已执行的具体场景，不代表对应模块的全部功能均已通过测试。

### 3.2 主要异常现象

现有缺陷记录中包含 BUG-001 至 BUG-006 六条记录，具体如下：

| 编号 | 异常现象 | 主要风险 |
|---|---|---|
| BUG-001 | 加入购物车后页面出现错误提示，但商品实际已添加 | 页面反馈与实际状态不一致，可能引起重复操作 |
| BUG-002 | 商品行内金额显示为 `$00.00`，底部总价计算正确 | 用户无法通过行内金额准确核对商品价格 |
| BUG-003 | 点击商品删除按钮后，商品仍保留在购物车中 | 用户可能无法正常移除商品 |
| BUG-004 | 重复添加已有商品时出现错误提示，数量未增加 | 影响购物车商品数量更新 |
| BUG-005 | 注册后使用相同凭据登录失败 | 账号创建状态尚未确认，暂时无法判断根本原因 |
| BUG-006 | 商品数量为 0 时购物车入口消失 | 用户可能无法通过该入口继续查看或修改购物车 |

上述内容记录的是测试过程中观察到的现象，并不代表所有问题均已完成根因分析。对于尚未排除环境因素或需求歧义的问题，应继续确认后再确定最终缺陷状态。

## 4. 缺陷分析与质量风险

### 4.1 操作反馈与实际状态不一致

添加商品时出现错误提示，但商品实际上已经加入购物车。这说明测试不能只根据页面提示判断操作结果，还需要进一步检查购物车状态、商品数量及金额变化。

如果用户将错误提示理解为操作失败并反复点击，可能产生重复操作或困惑。因此，建议后续重点检查前后端执行结果与页面提示之间的一致性。

### 4.2 购物车金额展示与计算

当前记录显示，部分商品行内金额为 `$00.00`，而购物车底部总价能够正确计算。

例如，Combination Pliers 单价为 $14.15，数量为 2；Pliers 单价为 $12.01，数量为 1，底部总价为 $40.31。

这表明金额展示与总价计算需要分别验证。即使最终总价正确，行内金额展示异常仍会影响用户核对订单金额的体验。

### 4.3 购物车操作完整性

删除商品按钮无响应、重复添加商品失败以及数量为 0 时购物车入口消失等现象，均与购物车操作的完整性有关。

后续分析应关注不同操作之间的状态一致性，例如商品删除后清单与总价是否同步更新、数量变化后入口状态是否合理，以及错误操作后用户是否仍能继续使用系统。

### 4.4 注册登录问题的确认边界

注册后无法使用相同凭据登录，但当前尚未确认账号是否真正创建成功。因此，现阶段只能记录操作现象，不能直接断定是注册功能或登录功能存在缺陷。

后续若需要继续验证，应先确认测试账号的创建状态及测试环境要求，再决定是否补充测试。

## 5. 测试限制

1. **环境限制：** 测试使用在线演示环境，无法完全控制服务端状态、测试数据和环境变更。
2. **账号限制：** 注册账号的创建状态尚未完全确认，注册登录流程的验证不完整。
3. **测试范围限制：** 当前主要覆盖部分 Web 功能及边界场景，未覆盖所有业务流程。
4. **自动化限制：** 当前以手工测试为主，尚未建立覆盖核心业务流程的完整自动化回归测试。
5. **缺陷分析限制：** 已记录的异常尚未全部完成根因分析，缺陷修复状态也未经验证。

因此，本报告属于当前测试阶段的总结，不应作为系统整体质量或生产环境稳定性的最终结论。

## 6. 后续改进计划

1. 复核 6 条缺陷记录，补充必要的复现步骤、截图及关联测试用例。
2. 区分已复现异常、待确认问题和需求待确认事项，避免将所有异常直接认定为已确认缺陷。
3. 优先选择稳定且重要的核心场景开展接口自动化测试，重点关注请求结果、关键字段和异常响应。
4. 完善 README、测试执行记录及 AI 辅助测试记录，确保项目材料之间相互对应。
5. 在具备可靠验证条件后，再对未确认的问题进行补充测试。

## 7. 总结

本项目围绕 Toolshop 电商 Web 系统开展了以功能测试为主的质量保障实践，覆盖商品搜索、分类筛选、商品详情、购物车及部分注册登录场景。

测试过程中不仅验证了正常业务流程，也关注了页面反馈与实际状态的一致性、金额展示与计算、购物车状态变化以及异常输入处理。现有记录中包含六条待进一步确认的异常，为后续风险分析和测试改进提供了依据。

本项目当前的主要价值在于通过真实执行场景发现问题、形成测试证据并进行风险分析。后续将继续完善缺陷确认、核心场景自动化验证及项目交付文档，使测试过程更可追溯、测试结论更有依据。
