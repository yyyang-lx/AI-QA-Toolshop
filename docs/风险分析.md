# Toolshop 电商系统风险分析

## 一、分析目的

本文件用于识别 Toolshop 电商系统中可能影响用户使用和业务流程的风险，明确优先测试的功能及后续验证方向，为测试用例设计和测试执行提供依据。

当前风险分析结合手工测试、API 自动化和 UI 自动化的现有记录。待确认事项仍保留为风险，不把一次观察直接当成根因已确认。

## 二、当前走查结果

### 2.1 已完成的初步检查

| 检查项 | 实际观察结果 | 当前结论 |
|---|---|---|
| 首页访问 | 首页正常打开 | 基本访问正常 |
| 商品列表 | 可以看到商品 | 商品列表基本展示正常 |
| 商品详情 | 可以进入商品详情页 | 基本页面跳转正常 |
| 商品搜索 | 搜索后有结果 | 搜索功能可以进行基本操作 |

### 2.2 当前验证局限

以上结果仅代表完成了基础走查，尚未充分验证：

1. 商品信息和搜索结果是否准确。
2. 分类筛选是否能够正确过滤商品。
3. 添加购物车、商品数量变化等操作是否符合预期。
4. 登录功能对正确和错误输入的处理是否合理。
5. 异常输入、重复操作和不同业务步骤组合场景是否正常。

因此，目前不能仅凭基础走查判断系统整体功能是否通过测试。

## 三、风险评估方法

本次采用业务影响和测试优先级相结合的方式进行初步分析。

- 高优先级：可能直接影响核心功能或用户完成主要业务流程，应优先设计用例并执行验证。
- 中优先级：可能影响部分功能使用、交互体验或数据展示，在核心场景之后进行验证。
- 低优先级：影响相对有限，可在核心功能验证完成后进一步检查。

当前优先级为初步判断，后续可根据实际测试结果调整。

## 四、主要风险识别

| 风险编号 | 风险场景 | 潜在影响 | 初始优先级 | 验证状态 |
|---|---|---|---|---|
| R01 | 搜索结果与关键词不匹配 | 用户难以找到目标商品，搜索功能不符合预期 | 高 | API 已覆盖有结果和无结果关键词；空关键词等 UI 场景仍待验证 |
| R02 | 分类筛选结果不准确 | 用户看到不属于目标分类的商品，或遗漏符合条件的商品 | 中 | 已有手工测试记录；需结合用例表核对完整执行状态 |
| R03 | 购物车添加、金额或删除行为异常 | 用户无法准确查看、修改购物车，可能影响购买流程 | 高 | UI 自动化观察到 BUG-001 至 BUG-003，状态待人工验证 |
| R04 | 登录输入校验或错误处理不合理 | 用户可能无法正常登录，或无法理解登录失败原因 | 高 | 最近一次本地运行中的正常登录、错误密码和缺少密码用例通过；注册后登录流程仍待确认 |
| R05 | 商品列表与详情页的信息不一致 | 用户可能根据错误的商品信息作出购买判断 | 中 | 已有手工核对记录，完整范围以用例执行表为准 |
| R06 | 页面操作反馈与真实状态不一致 | 用户无法判断操作是否成功，可能重复操作 | 中 | 添加购物车后错误提示但商品已加入，关联 BUG-001，待人工确认 |
| R07 | 在线演示环境或测试数据发生变化 | 测试结果可能受到网络、共享数据或系统更新影响 | 中 | 持续关注；API 与 UI 测试均依赖在线服务 |
| R08 | 自动化测试依赖不稳定的页面或测试数据 | 自动化脚本可能出现不稳定失败，影响结果判断 | 中 | UI 基础地址已配置化；商品未出现时标记为前置条件未满足，稳定性仍需后续运行观察 |

## 五、第一轮走查发现的异常

### 5.1 添加多个商品时出现异常

在 With Bugs 版本进行购物车走查时：

1. 第一个商品可以正常添加到购物车。
2. 后续尝试添加其他商品时，页面出现错误提示：
   `Oops, something went wrong.`

当前判断：

- 异常可以在实际操作中观察到。
- 目前尚未进一步确认触发条件。
- 尚不能确定是前端、接口、数据还是其他原因导致。
- 后续需要重复操作确认问题是否稳定复现。

因此当前将其记录为：

**购物车模块高风险问题，待进一步复现确认。**

---

### 5.2 购物车商品单项总价显示异常

在购物车页面观察到：

- Combination Pliers：数量为 2，单价为 $14.15，单项 Total 显示 `$00.00`
- Wood Saw：数量为 1，单价为 $12.18，单项 Total 显示 `$00.00`
- Pliers：数量为 1，单价为 $12.01，单项 Total 显示 `$00.00`
- 页面底部购物车总价显示 `$52.49`

根据商品数量和单价进行计算：

- Combination Pliers：2 × $14.15 = $28.30
- Wood Saw：1 × $12.18 = $12.18
- Pliers：1 × $12.01 = $12.01
- 合计：$52.49

因此，目前观察到：

**商品单项 Total 与商品数量、单价之间不一致，但购物车最终 Total 与计算结果一致。**

当前判断：

- 属于金额展示一致性风险。
- 需要进一步确认修改数量、删除商品、重新进入购物车后是否仍然存在。
- 暂不判断具体原因。
- 后续需要作为重点测试场景进行复现。

优先级：高

状态：已观察到，待进一步确认。

## 五、重点风险的验证思路

### 5.1 搜索功能（R01）

API 自动化已覆盖匹配关键词和无结果关键词，并校验搜索结果中的商品名称。后续可补充空关键词、仅空格、关键词大小写和分页等页面行为检查。

### 5.2 分类筛选（R02）

后续可依据测试用例表补充核对分类商品归属、空结果反馈及搜索与分类组合筛选，避免将用例表中的计划状态误当作已执行结果。

### 5.3 购物车（R03）

UI 自动化已覆盖添加商品、查看数量、错误提示、行金额及删除操作。后续复核应重点确认 BUG-001 至 BUG-003 的复现稳定性，并补充重复添加、数量修改、刷新及多商品组合场景。

### 5.4 用户登录（R04）

API 自动化已覆盖正常登录、错误密码及缺少密码；注册后登录失败的现象仍需先确认账号是否创建成功，再判断归属。

不得在未执行的情况下，将预期中的异常记录为实际缺陷。

## 六、测试优先级安排

第一优先级：

- 商品搜索结果准确性。
- 购物车添加及商品数量相关操作。
- 登录输入校验与基本登录流程。

第二优先级：

- 商品分类筛选。
- 商品列表与详情页信息一致性。
- 操作反馈和页面异常状态。

持续关注：

- 在线演示环境的可用性。
- 测试数据变化。
- 后续自动化脚本的稳定性。
