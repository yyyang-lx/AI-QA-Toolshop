# Toolshop 测试用例设计说明

## 一、设计目的

针对 Practice Software Testing 的 With Bugs 版本，围绕电商系统的核心业务功能设计测试用例，验证主要功能是否符合预期，并识别异常处理、数据一致性及业务流程方面的潜在问题。

## 二、测试对象

- 被测系统：Practice Software Testing（Toolshop）
- 测试版本：With Bugs（Bug Hunting Mode）
- 测试方式：手工功能测试为主，自动化测试为辅
- 测试阶段：测试用例设计阶段

## 三、用例设计方法

### 3.1 等价类划分

将输入划分为有效和无效情况。例如，商品搜索可以测试有匹配结果的关键词、无匹配结果的关键词以及空关键词。

### 3.2 边界值分析

关注数量输入、必填项和其他具有边界限制的字段。具体边界应以系统实际规则为依据。

### 3.3 场景法

按照用户的实际业务流程设计用例，例如浏览商品、查看详情、添加购物车以及进入登录流程。

### 3.4 异常测试

关注重复操作、无效输入、操作失败提示和数据不一致等情况。

### 3.5 数据一致性验证

对商品单价、数量、单项总价和购物车总价进行核对，检查页面数据是否符合计算规则。

## 四、测试优先级

- P0：核心业务或金额数据相关场景，优先验证。
- P1：主要功能的正常流程和常见异常场景。
- P2：补充场景、交互体验和其他边界情况。

优先级用于安排测试顺序，不代表缺陷严重程度。

## 五、测试结果记录规则

每条用例应包含用例编号、所属模块、用例标题、前置条件、操作步骤、测试数据、预期结果、优先级、实际结果和执行状态。

执行状态统一使用：

- 未执行
- 通过
- 失败
- 阻塞

测试结果必须以实际执行为依据。对于尚未执行的用例，只填写预期结果，不预先填写通过或失败。

## 六、后续安排

1. 完成核心模块测试用例设计。
2. 检查用例是否覆盖正常、异常、边界和数据一致性场景。
3. 在 Day 3 执行用例并记录实际结果。
4. 根据真实执行结果完善缺陷记录。
5. 在 Day 4 选择适合自动化的稳定场景进行实践。
